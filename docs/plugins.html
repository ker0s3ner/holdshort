Plugins

Plugins run in a sandboxed iframe with a live, read-only feed of traffic and airport data — real third-party code, not a built-in extra pretending to be one.

Each plugin is a single static HTML file, loaded in an <iframe sandbox="allow-scripts"> with no allow-same-origin — it gets its own opaque origin and genuinely cannot read the app's localStorage, DOM, or cookies. The host posts a message roughly once a second with the controlled airport's position and every aircraft's callsign, type, state, and real-world origin/destination coordinates; the plugin does whatever it wants with that. It's read-only for now — a plugin can't issue clearances or otherwise write back into the sim yet. That's real future work, not a corner cut: safely letting untrusted code control the simulation is its own design problem.

World Traffic Map

A VatSpy-style world map showing where each aircraft in your current session is really flying to or from. It only knows about traffic in your own local sim — there's no shared network connecting separate Holdshort sessions together yet, so it can't show other players. The reference implementation for the plugin SDK — its source is plain HTML/JS, no build step, a good starting point for your own.

Building your own

A plugin is one HTML file. Listen for message events, check for e.data.type === "holdshort:tick", and render whatever you want from homeAirport, aircraft, and theme — then post { type: "holdshort:ready" } to window.parent once your listener is attached so the host knows to start sending data. The full protocol is documented in src/pluginProtocol.ts; the World Traffic Map plugin's source (public/plugins/worldmap/index.html) is a complete working example. There's no install-from-URL flow yet — for now, shipping a plugin means it lives in the app's own public/plugins/ directory — open a PR or an issue on GitHub.
